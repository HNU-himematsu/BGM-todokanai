# 审查基线与验证规格

## 基线

审查对象为 `origin/main` 提交 `233f2183597e3a6aa21c3dc7b7276e02b9db6cca`，基线通过 `git fetch --all --prune` 获取，工作分支经 `git merge --ff-only origin/main` 对齐。基线包含线上独立答题、线下时间轴、三类榜单、OSS 音频与发布流水线。

## 验证隔离

`git archive HEAD` 提取的源码位于 Git 忽略目录 `work/review-233f218/source/`。基线测试和构建只使用受 Git 管理的文件；业务探针使用临时目录、测试题库和模拟音频地址。正式题库、音频、活动成绩及用户编辑不属于验证输入。

## 验证目标

| 范围 | 判定标准 |
| --- | --- |
| 干净检出 | CI 命令不依赖未跟踪题库和本地环境数据 |
| 暂停计时 | 提交发生在暂停期间或恢复之后时，计时有一致且明确的规则 |
| 结算失败 | JSON 与 TXT 各自失败具有明确结果、可重试性与通知边界 |
| 本地恢复 | 进度失效或身份切换不保留另一尝试的运行标识 |
| 主持人重连 | 状态快照与音频位置、播放状态保持一致 |
| 发布回滚 | 清理历史版本时保留当前软链接目标；重启命令失败也执行恢复 |
| 题集版本 | 字段变化与缓存失效规则具有明确覆盖范围 |

## 证据等级

- 运行确认：构建、测试或隔离探针已观测。
- 静态确认：源码调用链及输入条件能确定行为。
- 设计边界：行为符合文字规格，但存在需要业务选择的风险。
- 待测：设备、网络、素材、容量及生产环境事实需要外部实测。

探针通过表示所描述行为得到复现，不表示系统通过目标规格验收。源码事实、目标建议和外部部署状态分别陈述。
