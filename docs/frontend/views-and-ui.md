# 页面视图与交互规范

## 1. 视图构成与职责划分

前端系统包含三个核心视图，覆盖参与者旅程与后台场控流程：

```text
┌─────────────────┐       登记昵称       ┌─────────────────┐
│  JoinView.vue   │ ───────────────────> │  PlayView.vue   │
│ (扫码登记与准入) │                      │ (答题与个人结算) │
└─────────────────┘                      └─────────────────┘

┌─────────────────┐
│  HostView.vue   │ (主持人现场调度、放音监控与全场控制)
└─────────────────┘
```

视图进入方式：
- `HostView.vue` 仅能通过直接输入网址 `/host` 进入，前端各页面均不设置指向该视图的跳转链接。
- `JoinView.vue` 与 `PlayView.vue` 面向参与者，页面内不提供主持人控制台入口。

## 2. 参与者登记页 (`JoinView.vue`) 交互设计

登记页仅保留两个内容区块，其余说明性元素均不渲染：

1. **主题标题区**：
   - 活动主题标题（「旮旯原声之届不到的 BGM」）以超大字号呈现，作为页面的视觉主体。
   - 标题下方不渲染玩法介绍段落，也不渲染「多人同步答题」「共 X 题」等元信息图标行。
2. **入场表单区**：
   - 提供昵称输入框与「进入活动」主按钮，输入校验失败或连接异常时以警示条提示。

## 3. 参与者移动端 (`PlayView.vue`) 交互设计

针对户外高光、小屏手机使用场景深度优化：
1. **就绪等待状态**：
   - 顶部显示“等待主持人发题...”提示徽标。
   - 显示已登记的个人昵称与当前在线总人数。
2. **答题进行状态**：
   - **动态倒计时条**：顶部渲染 20 秒渐变收缩动画条，直观反映剩余作答窗口。
   - **曲目与难度标签**：标题上方以彩色标签渲染放音编号（如「音频 TRACK-01」）、题目类型（「氛围题」/「作品题」）与难度等级（「简单」/「中等」/「困难」）。
   - **单选操作卡片**：4 个大尺寸自适应按钮。参与者点击选项后，按钮立即进入锁定状态并高亮边框，防止重复点击。
3. **答案揭晓状态**：
   - 倒计时归零后，系统自动标记选项结果：正确选项高亮为翠绿色，若参与者选错则所选项高亮为红色。
   - 底部滑出半透明文本卡片，展示详细解析内容。
4. **结算排名状态**：
   - 最后一题结束后，页面自动展示“本轮挑战完成”结算卡片。
   - 突出显示个人最终得分、累计作答总耗时（精确至小数点后一位，例如 `14.2 秒`）。
   - 下方展开本轮完整排行榜，标明各玩家的名次、昵称与答题用时。

## 4. 主持人控制台 (`HostView.vue`) 交互设计

针对笔记本电脑宽屏控制台设计，信息呈模块化分区呈现：
1. **顶部流程与模式控制栏**：
   - 提供「一键开始轮转」、「暂停自动轮转」、「恢复轮转」、「重置活动」等主操作按钮。
   - 提供自动模式切换开关，支持随时在全自动与纯手动调度间无缝切换。
2. **放音协同指示看板**：
   - 屏幕中央显眼位置使用超大字号展示当前放音编号（例如 `当前放音：TRACK-03`）。
   - 同步标明建议播放区间（15~25 秒）与作品提示，便于场地放音人员瞥视确认。
3. **现场作答进度监控墙**：
   - 实时罗列当前房间所有在线玩家卡片。
   - 参与者完成提交后，对应卡片立即标记绿色勾选图标，并实时统计“已作答人数 / 在线总人数”。
4. **结算榜单与去重导出**：
   - 活动结束后自动渲染本轮排名表格。
   - 提供下载或在线查看 `leaderboard_summary.txt` 按钮，便于核对全场总榜与去重奖品榜。

## 5. 界面设计与文案规范

- 界面尽可能减少非必要元素，各页面仅保留最简要的必要文字说明。
- 界面文案统一使用中文，各页面不出现英文装饰性小字（标题上方的大写英文眉题）。
- 版式层次通过中文标题、正文与间距呈现，不使用英文小字作为视觉点缀。
- 放音代号（如 `TRACK-01`）属于数据编号，与现场音箱播放列表文件名严格对应，界面中以「音频：TRACK-01」「当前放音：TRACK-01」等中文标签承载。
