# 页面视图与交互规范

## 1. 视图构成与职责划分

前端系统包含三个核心视图，覆盖参与者旅程与后台场控流程：

```text
┌─────────────────┐       登记昵称       ┌─────────────────┐
│  JoinView.vue   │ ───────────────────> │  PlayView.vue   │
│ (扫码登记与准入) │                      │ (答题与个人结算) │
└─────────────────┘                      └─────────────────┘

┌─────────────────┐
│  HostView.vue   │ (轮次切换、音频播放、时间轴调度与全场控制)
└─────────────────┘
```

视图进入方式：
- `HostView.vue` 仅能通过直接输入网址 `/host` 进入，前端各页面均不设置指向该视图的跳转链接。
- `JoinView.vue` 与 `PlayView.vue` 面向参与者，页面内不提供主持人控制台入口。

顶部导航栏：
- 站点顶部品牌导航栏仅在参与者答题页 (`PlayView.vue`) 渲染，右侧「参与者」入口用于返回登记页。
- 登记页 (`JoinView.vue`) 不渲染站点顶部品牌导航栏，页面自主题标题直接开始。
- 主持人页面（登录页与控制台）不渲染站点顶部品牌导航栏，页面内不出现「参与者」标识。

## 2. 色彩体系与视觉阅读舒适度规范

系统采用以亮兰紫 `rgb(188, 74, 216)`（十六进制 `#BC4AD8`）为主色系的全局视觉体系。在保证鲜明活泼品牌辨识度的同时，重点优化移动端小屏设备与现场光照环境下的阅读舒适度与视觉耐受度。

### 2.1 主色系与衍生阶元

主色系以 `--accent` 系列设计令牌承载，定义点与派生配方见 [`frontend-architecture.md`](frontend-architecture.md) 第 7 节；全部阶元由主色单点驱动，更换主色时同步联动。下列为主色 `rgb(188, 74, 216)`（`#BC4AD8`）下的渲染结果：
- **品牌视觉主色 (`--accent`)**：`rgb(188, 74, 216)`（十六进制 `#BC4AD8`）。作为系统核心主色，应用于主题标题核心字眼强调、主操作实体按钮底色、选项选中边框高亮、音频剩余时间条填充、得分核心数值以及控制台关键编号。该色彩在纯白背景下具备 4.11:1 的对比度，文字与边框鲜明醒目。
- **主色深阶 (`--accent-dark`)**：`#8D38A2`。用于按钮悬停与按压态、激活态链接、重点文字标签以及个人在排行榜中的高亮名次。在浅色背景下提供 6.52:1 的对比度，达到 WCAG AA 级标准，确保关键状态与重点数据的锐利识别。
- **主色中间阶 (`--accent-mid`)**：`#D691E9`。用于排行榜第二名徽章底色，与头名、第三名构成同色相的明度递进。
- **主色浅阶 (`--accent-line`)**：`#EDCCF6`。用于排行榜第三名徽章底色与轻量强调边框，勾勒清晰而温和的层级分界。
- **主色柔和底衬 (`--accent-light`)**：`#FCF5FD`。用于单选项选中状态的背景填充、提示卡片淡色衬底。低饱和浅淡兰紫底色消除深色大面积色块的视觉压迫，为长时间连续作答保持轻松的眼部体验。

### 2.2 舒适阅读与对比度规范

排版体系遵循 WCAG 2.1 AA/AAA 级无障碍可读性准则，消除因色彩对比生硬或对比度不足导致的视力疲劳：
- **文本对比度阶梯**：
  - **核心标题与正文文本 (`--ink`)**：采用深灰黑 `#171717`。在纯白背景下形成 16.1:1 的超高对比度，确保文字轮廓清晰锐利。避免使用极端纯黑 `#000000`，有效消除极端黑白对比引发的眩光。
  - **次级说明与辅助文本 (`--muted`)**：采用舒适中灰 `#595959`。在纯白背景下对比度保持在 7.0:1，完全满足 WCAG AAA 级（文本 ≥ 7:1）标准。层次分明的同时，保证辅助规则与说明文字字字清晰易读。
  - **三级辅助与时间戳文本**：采用柔灰 `#8C8C8C`，用于次要元数据与非关键辅助标记，对比度保持在 3.3:1 以上。
- **底衬与卡片呼吸感**：
  - 主页面背景底色采用纯净白 `#FFFFFF` 与柔灰白 `#FAFAFA`。
  - 卡片与面板采用纯白 `#FFFFFF`，边框采用浅柔灰 `#EAEAEA`，阴影使用超轻扩散弥散阴影（`0 18px 45px rgba(0, 0, 0, 0.045)`），杜绝厚重黑框与生硬暗影，营造舒缓呼吸空间。
- **排版比例与行高标准**：
  - **标题行高**：设置在 1.15 至 1.3 之间，辅以微紧字距（`-0.02em` ~ `-0.03em`），保持紧凑醒目的视觉张力。
  - **正文与说明行高**：保持在 1.6 至 1.75 之间，段落与表单字段间距保持充足留白（20px ~ 28px），确保多行文本在小屏设备上具备流畅舒适的换行阅读节奏。

### 2.3 语义状态色搭配规范

系统语义状态色与主色系在明度与色相上保持平衡协调：
- **正确 / 成功状态 (`--green`)**：深翠绿 `#168267`，浅绿衬底 `#F1FBF8`。用于正确答案揭晓、已提交勾选与在线就绪指示。
- **错误 / 警示状态 (`--danger`)**：温润珊瑚红 `#C94A42`，浅粉衬底 `#FFF3F2`。用于答错选项标识与警示提示，警示明确且柔和不刺眼。
- **警告 / 观战过渡状态 (`--warning`)**：暖琥珀金 `#D48806`，浅金衬底 `#FFFBE6`。
- **音频剩余时间条配色**：本题音频段的剩余时间条以系统主色 `rgb(188, 74, 216)`（`--accent`）平涂填充，条内不叠加深翠绿、暖琥珀金等其他色相。时间条依据音频段起止时刻计算，作答截止时刻由编排中的 `LOCK` 动作决定。

## 3. 参与者登记页 (`JoinView.vue`) 交互设计

登记页仅保留主题标题区与入场表单区两个内容区块，日语小字属于主题标题区，表单内的基本必要说明文字全部保留：

1. **主题标题区**：
   - 标题上方显示日语小字「届かないメロディー」，与主标题左边缘对齐，采用 `--muted` 色与较小字号，作为主标题的轻量视觉前缀；小字不使用全大写拉丁字母，也不占据独立的大面积留白。
   - 活动主题标题（「旮旯原声之届不到的 BGM」）以海报式超大字体呈现：标题固定排为「旮旯原声之」「届不到的」「BGM」三行，手机端渲染字号约为屏幕宽度的 17%（`clamp(48px, 17vw, 96px)`），三行标题块的纵向高度约占屏幕上半段（视口高度的一半）的 50%，构成页面的视觉主体。
   - 日语小字与三行标题共同构成标题组，标题组完整容纳于上半段与版心之内；三行标题的宽度均不超过版心，页面不出现横向滚动，标题文字不被屏幕边缘裁切；标题字号随屏幕宽度收缩，极窄机型上「BGM」整体折至下一行。
   - 核心强调词（「BGM」）采用主色着重渲染，形成明快舒适的视觉焦点。
   - 手机端视口纵向对半分区：主题标题区占据上半段，日语小字与三行标题作为整体在区内垂直居中；入场表单卡片占据下半段并撑满该区，两个区块各占约 50% 视口高度。
   - 登记页不渲染站点顶部品牌导航栏与站点页脚，页面自主题标题直接开始。
   - 标题下方不渲染玩法介绍段落，也不渲染「多人同步答题」「共 X 题」等元信息图标行。
2. **入场表单区**：
   - 保留「准备入场」引导词、「先给自己起个名字」表单标题与「最终排行榜会显示这个昵称。别害羞，名字越有记忆点越好。」昵称说明。说明文字使用 `#595959` 舒适中灰与 1.65 宽舒行高，杜绝文字拥挤。
   - 昵称输入框聚焦边框呈现主色柔光态，提供明确的操作反馈。
   - 提供「进入活动」主按钮，采用主色实体背景与白字，悬停和激活状态呈现主色深阶；输入校验失败或连接异常时以温润警示条提示。
   - 表单下方保留「等待主持人开始后，所有人会同时进入答题」状态提示。
   - 轮次切换或活动重置后参与者由答题页返回本页时，昵称输入框自动回填本地保存的内容，无需重复输入。
   - 手机端表单卡片收紧内部间距以完整容纳于下半区，极矮机型上表单内容在卡片内滚动查看。
3. **规则说明弹窗**：
   - 触发时机：参与者在入场表单中输入有效昵称并点击「进入活动」后，触发规则说明弹窗。
   - 弹窗尺寸与布局：
     - 弹窗尺寸略微小于整个页面：移动端宽度占视口宽度的 92%（`width: min(92vw, 520px)`），最大高度占视口高度的 88%（`max-height: 88vh`），四周保留均匀的留白与半透明遮罩层，强化沉浸聚焦感同时保持模态弹窗层级关系。
     - 弹窗内部提供独立纵向滚动通道，在紧凑屏幕设备上平滑阅读所有规则项与主按钮。
   - 规则内容与文案：
     - 弹窗顶部标明「答题规则」标题与简要指引说明。
     - 核心规则围绕等待音乐播放与同步答题展开，分为清晰的流程要点：
       1. **现场音乐播放**：主持人控制台播放单一音频文件，现场音箱输出当前轮次的旋律片段。
       2. **题目上屏**：时间轴到达 `NEXT` 标记或主持人手动推进后，手机端同步呈现题目与选项。
       3. **限时作答**：参与者在 `LOCK` 标记到达或主持人手动锁卷前选定选项并提交。
       4. **揭晓与结算**：时间轴到达 `REVEAL` 标记后公布正确答案与解析，`FINISH` 标记触发结算并展示最终得分与排行榜。
   - 交互操作与流转：
     - 弹窗底部提供「我已了解，进入活动」主操作按钮，按钮撑满弹窗可用宽度，采用主色实体填充与白字，悬停和激活态呈现主色深阶。
     - 点击主按钮后发起入场注册并跳转至答题页 (`PlayView.vue`)。
     - 弹窗支持右上角关闭或点击遮罩关闭，关闭后停留在登记表单，便于参与者修改昵称。

## 4. 参与者移动端 (`PlayView.vue`) 交互设计

针对户外高光、小屏手机使用场景深度优化。

页面由主答题栏与分数侧栏两个区块组成，渲染范围随活动状态确定：
- `WAITING`、`ANSWERING`、`ANSWER_LOCKED` 与 `ANSWER_REVEALED` 状态下，页面仅渲染主答题栏，主答题栏占满版心宽度，不渲染分数侧栏，也不渲染分数保密占位提示块。
- `FINISHED` 状态下渲染分数侧栏，承载个人最终得分摘要与本轮排行榜；手机端置于主答题栏下方，宽屏端与主答题栏并排。
- **页面标题区域**：位于主答题栏顶部，左侧为标题文本，右侧为「退出本次参与」入口，标题文本采用页面级标题的字号与字重，作为答题界面的首要阅读对象。活动主题标题仅在 `WAITING` 状态下出现于该区域。
  - `WAITING` 状态下，标题文本为活动主题标题「旮旯原声之届不到的 BGM」，取自活动配置的 `eventName`，按单行文本呈现。
  - `ANSWERING`、`ANSWER_LOCKED` 与 `ANSWER_REVEALED` 状态下，标题文本为当前题目的题干：题干顶替活动主题标题在该区域的位置，随题目切换整体替换，题干不在题目卡片内重复渲染。
  - `FINISHED` 状态下，标题文本为结算态标题「本轮结算」，该状态下不渲染活动主题标题。
- 主答题栏的中文状态标题上方使用日语小字：等待态「開始を待っています」、作答态「問題に挑戦」、锁卷态「回答を締め切りました」、揭晓态「答え合わせ」、结算态「結果発表」。日语小字采用 `--muted` 色与紧凑字号，不替代中文状态信息或操作文案。

1. **就绪等待状态**：
   - 顶部显示“等待题目上屏...”提示徽标；轮次时间轴启动后，题目仍在 `NEXT` 标记到达时上屏。
   - 中心圆形等待指示图标呈现主色细线勾勒。
   - 显示已登记的个人昵称与当前在线总人数，多题轮转时可呈现下一题题号。
   - 就绪等待卡片专注于展示联机就绪与发题等待状态，不展示规则说明段落。
2. **答题进行状态**：
   - **音频剩余时间条**：顶部渲染主色收缩动画条，反映本题音频段剩余时间；进度与数值基于 `questionAudioStartEpochMs` 与 `questionAudioEndEpochMs` 计算，时间轴暂停时同步冻结。音频段终点仅决定时间条显示，提交入口由 `canAnswer` 与 `ANSWERING` 状态控制。
   - **题目类型标签**：题目卡片顶部以彩色标签渲染题目类型（「氛围题」/「作品题」），与音频剩余时间同行呈现；不渲染放音编号标签或难度等级标签。
   - **单选操作卡片**：4 个大尺寸自适应选项。未选中时采用细柔灰边框；参与者选中选项后，边框高亮为主色，背景填充为主色柔和底衬，左侧选项字母徽章填充为主色与白字。点击确认提交后依据 `hasAnswered` 和 `selectedOption` 锁定选择，重复提交与超时提交均不可用。
3. **已锁卷状态**：
   - `LOCK` 标记或主持人手动锁卷后，界面标记“答题已结束”，选项保持只读；正确答案与解析保持隐藏，等待 `REVEAL`。
4. **答案揭晓状态**：
   - 揭晓后系统标记选项结果：正确选项高亮为深翠绿 `#168267`（背景 `#F1FBF8`），若参与者选错则所选项高亮为珊瑚红 `#C94A42`（背景 `#FFF3F2`）。
   - 底部滑出半透明文本卡片，展示详细解析内容；揭晓画面保持到下一题上屏。
5. **结算排名状态**：
   - `FINISH` 结算后，页面自动展示“本轮挑战完成”结算卡片。
   - 突出显示个人最终得分、累计作答总耗时（精确至小数点后一位，例如 `14.2 秒`），得分数字采用主色呈现。
   - 分数侧栏内展开本轮完整排行榜，标明各玩家的名次、昵称与答题用时；本人所在行以主色深阶高亮并加粗展示。
   - 提供返回登记页入口；轮次切换或活动重置清空玩家后页面回到登记页，昵称自动回填。`ROUND_ENDED` 只暂停音频与时间轴，不触发结算或清空玩家。

## 5. 主持人控制台 (`HostView.vue`) 交互设计

控制台以手机端为优先适配目标，手机端各分区单列纵向堆叠，宽屏端保持多列模块化分区呈现：
1. **页头状态栏**：
   - 控制台中文标题上方显示日语小字「進行管理」，登录页中文标题上方显示「管理者ログイン」。小字采用 `--muted` 色，字号小于中文标题，不取代身份验证或状态信息。
   - 展示在线人数与当前活动状态徽标（如「等待开始」）；页头不渲染「自动轮转模式」标签或「退出」按钮。
2. **轮次与播放控制栏**：
   - 轮次选择器展示轮次名称及音频区间，选项来自轮次清单；切换轮次会清空在线玩家并回到 `WAITING`，提交前展示明确的影响确认。时间轴运行且未暂停时禁用切换。
   - 提供「开始播放」「暂停」「恢复」「重置活动」主操作。开始播放将音频定位到选中轮次的 `startMs` 并调用启动接口建立时间轴零点；启动请求失败时停止本地播放并保留错误提示。
   - 仅在 `WAITING` 且时间轴未运行时提供「开始播放」；运行时提供「暂停」，暂停时提供「恢复」；重置活动清空在线玩家并回到 `WAITING`，执行前展示确认。
3. **音频与时间轴看板**：
   - 展示当前轮次名称、`startMs` 至 `endMs` 的音频区间、音频播放进度与「待启动 / 运行中 / 已暂停 / 已结束」状态；音频播放器为现场音箱的播放源。
   - `ACTIVITY_PAUSED`、`ACTIVITY_RESUMED`、`ROUND_ENDED` 与 `ACTIVITY_RESET` 分别驱动音频暂停、恢复、停在轮次结束标记与回到轮次起点；断线重连时重新获取主持人快照并校准控制状态。
   - `ROUND_ENDED` 只表示轮次音频及时间轴停止；结算与榜单归档由 `FINISH` 标记触发。
4. **题目与作答进度**：
   - 题目预览展示当前题号、题型、题干及主持人可见的作品提示；`LOAD` 只填充服务端待上屏槽位，参与者屏幕在 `NEXT` 前保持原状态。
   - 玩家列表按当前题展示已提交标记与「已作答人数 / 在线总人数」；`ANSWER_LOCKED` 状态区分已提交与未提交玩家，`ANSWER_REVEALED` 状态展示揭晓结果。
5. **手动兜底控制**：
   - 提供「锁卷」「揭晓答案」「下一题」按钮；「锁卷」仅在 `ANSWERING` 可用，「揭晓答案」仅在 `ANSWER_LOCKED` 可用，「下一题」仅在 `WAITING` 或 `ANSWER_REVEALED` 显示为可操作。待上屏题目是否存在由服务端状态守卫判定。
   - 手动操作与时间轴使用相同状态流转，成功后刷新主持人快照；不满足状态守卫时展示服务端业务错误，不在客户端推测或强行更新状态。
6. **结算榜单与去重导出**：
   - `FINISHED` 状态渲染本轮排名表格。排行榜头名徽章使用主色实体填充，第二名与第三名徽章分别采用主色中间阶与主色浅阶底色。
   - 提供下载或在线查看 `leaderboard_summary.txt` 按钮，按钮以主色文本高亮，便于核对全场总榜与去重奖品榜。
7. **手机端适配规范**：
   - 页头标题与状态栏纵向排列，状态栏横向铺满整行；轮次与播放控制、音频时间轴、扫码加入、题目预览、作答进度与排行榜各区依次单列堆叠。
   - 流程操作按钮全宽纵向堆叠，触控面积保持充足；轮次选择与可能清空玩家的确认内容完整可读，页面上下留白与各区间距适度收紧。
   - 扫码加入区的说明文字与二维码纵向排列，二维码水平居中；登录页收紧纵向留白，登录区域宽度随版心自适应。

## 6. 界面设计与文案规范

- 界面尽可能减少非必要元素，各页面仅保留最简要的必要文字说明；基本必要的操作与状态说明文字全部保留。
- 页面排版避免大面积留白，内容以实际渲染字号紧凑呈现，不通过放大占位区域替代字号。
- 主要标题、状态、操作、错误提示及规则说明使用中文；标题上方的装饰性小字使用日语，日语小字不承担唯一的信息传达职责。
- 日语小字仅出现在页面主题标题、状态标题或登录标题上方，使用自然的日语短语、`--muted` 色与紧凑字号；不使用英文装饰性眉题，不增加与流程无关的说明段落。
- 版式层次通过中文标题、日语小字与间距呈现，日语小字与后续标题形成同一视觉组，不遮挡标题、状态或操作控件。
- 活动主题标题仅出现在登记页主题标题区与答题页的等待态标题区域，文案统一为「旮旯原声之届不到的 BGM」，不出现其他活动代称。
