# 主持人播报与完整音频合成规范

## 1. 文档用途

本文定义主持人播报（绫地宁宁）12 段语音接入猜歌活动的规则：素材清单、播报在完整音频中的落点与槽位长度、四轮对位表、轮首播报槽位、时间轴重算规则、生成流程、校验方法与现场表现。

含播报母带只服务线下模式；线上模式的纯 BGM 母带与双编排配置见 [`dual-master-audio.md`](dual-master-audio.md)。

读者对象为素材制作方、数据生成者与现场执行者。编排文件的通用契约见 [`timeline-spec.md`](timeline-spec.md)，活动的题库与轮次数值见 [`jisong-event-integration.md`](jisong-event-integration.md)，编码与定位指标见 [`audio-seek-quality.md`](audio-seek-quality.md)。

## 2. 接入形态

播报以离线合成方式进入线下母带，每台设备运行期只有一个音频文件、一个播放器。

- 含播报母带只服务线下主持人控制台，对象为 `bgm/event-offline.mp3`；线上参与者播放纯 BGM 对象，内容不含播报。
- `backend/data/event-demo.mp3` 是单母带中间产物，`backend/data/event-offline.mp3` 是四轮成品；上传到 OSS 后，部署服务器不保存该文件。
- 播报片段只在生成阶段使用，不放入 `backend/data`，不通过接口提供，不参与运行期加载。
- 播报槽位落在本题音乐终点之后的静音段内，播报贴近下一题音乐起点；播报结束到下一题音乐之间保留 400 毫秒静音，槽前余量位于播报之前。

实时叠加要求每台设备同时播放两个媒体元素。移动端浏览器的并发播放策略、时钟漂移，以及线上的跳题、切后台暂停与进度恢复，都会让两个元素失去同步。单文件合成让上述行为直接沿用现有实现。

## 4. 对位规则

| 项目 | 规则 |
| :--- | :--- |
| 槽位起点 | 本题音乐终点 |
| 播报结束 | 下一题音乐起点前 400 毫秒 |
| 前置留白 | 至少 200 毫秒，位于播报之前 |
| 尾部留白 | 400 毫秒 |
| 槽长 | 片段时长 + 600 毫秒 |
| 新空档 | `max(原空档, 槽长)` |
| 插入量 | 新空档 − 原空档 |
| 槽前余量 | 新空档 − 槽长 |
| 播报开始到上一题音乐 | 200 毫秒 + 槽前余量 |

- 原空档取编排文件的「本题音乐片段结束」到「下一题音乐片段开始」之间的时长；每轮第 10 题取到本轮 `endMs`。
- 播报锚定在空档末端：播报结束 400 毫秒后进入下一题音乐。装得下的空档保持原长，余量静音放在播报之前；装不下的空档按槽长加长，延长的时间同样放在播报之前，后续音乐整体后移。
- 开幕置于文件起点，槽长 33535 毫秒（32935 + 600），前置留白 200 毫秒。第一轮 `startMs` 取 0，第 1 题 `audioStartMs` 取 0，音频窗口包含开幕段。
- 第二至四轮轮首槽位取开幕段整段，槽起点为本轮 `startMs`，前置留白 200 毫秒，槽长 33535 毫秒；本轮首题音乐起点为 `startMs + 33535`，首题 `audioStartMs` 取本轮 `startMs`，音频窗口包含轮首播报段。
- 轮末《结束改》位于本轮空档末端，结束于下一轮 `startMs` 前 400 毫秒；下一轮轮首《开幕》紧随其后。
- 谢幕追加在第四轮末尾，是槽长规则的例外：片段之后没有下一题音乐，只保留 300 毫秒尾部留白，槽长 2210 毫秒（1910 + 300）。第四轮 `endMs` 随之后移，母带以该段静音收尾。

## 6. 时间轴重算

### 6.1 锚定规则

线下编排把播报段计入下一题的音频窗口：第 2 至 10 题的窗口从本题播报段起点开始，轮首题的窗口从本轮 `startMs` 开始。播报段起点指播报片段前 200 毫秒槽前余量的起点。

| 条目 | 锚点 | 取值 |
| :--- | :--- | :--- |
| `LOAD.atMs` | 本题播报段起点 | −1000；本轮首题取本轮 `startMs` |
| `NEXT.atMs` | 本题播报段起点 | 0；本轮首题取本轮 `startMs` +1 |
| `LOCK.atMs` | 下一题播报段起点 | −3000；轮末题取本轮 `endMs` − 3000 |
| `REVEAL.atMs` | `LOCK` | +1000 |
| `FINISH.atMs` | 轮末 | 本轮 `endMs` |
| `audioStartMs` | 本题播报段起点 | 每轮首题取本轮 `startMs` |
| `audioEndMs` | 下一题播报段起点 | 轮末题取本轮 `endMs` |

`NEXT` 上屏本题时，播放位置正是本题播报段起点：主持人先播报，播报结束保留 400 毫秒静音后进入本题音乐。`LOCK` 位于下一题播报开始前 3 秒，作答在下一题播报开始前关闭。

| :--- | :--- | ---: | ---: |

### 6.3 数据不变量

在 [`timeline-spec.md`](timeline-spec.md) 第 8 节之外，本活动的数据同时满足：

1. 每个播报片段的结束时刻与下一题音乐起点之间为 400 毫秒。
2. 每题音频窗口从本题播报段起点开始，播报片段完整落在本题窗口内，不落入上一题窗口。
3. 每轮第 10 题的播报片段仍位于本轮末尾，早于 `FINISH` 时刻结束；第二至四轮的 `FINISH` 位于下一轮轮首。
4. 谢幕片段结束后保留 300 毫秒静音，母带以静音收尾。
5. 末题 `audioEndMs` 等于母带总长 2429278。
6. 相邻题的 `audioEndMs` 与下一题 `audioStartMs` 相等，第一题 `audioStartMs` 为 0。
7. 每轮首题 `audioStartMs` 等于本轮 `startMs`，`NEXT.atMs` 等于本轮 `startMs + 1`。
8. 每题 `audioStartMs <= NEXT.atMs < LOCK.atMs < REVEAL.atMs <= audioEndMs`。

## 7. 生成流程

### 7.1 工具与输入

生成器为 `tools/build_voice_mix.py`，输入如下：

- `music/编排.docx`：40 题的音乐片段起止与四轮名义时长。
- `work/voice-extract/`：12 段播报素材与 `manifest.json`，由 `tools/extract_voice_clips.py` 生成。
- `music/bgm-music.mp3`：纯 BGM 题集母带。
- `backend/data/timeline.json`：线下编排的轮次 id、名称、题号与题目序列。
- `backend/data/timeline-online.json`：线上编排模板，提供轮次 id、名称与 `audioFile`。

编排文件的时间码用于定位候选区间；音频的实际出声点与静音区间由 `--align-audio` 检测，偏差超过 8 秒时生成失败。

编排文件中的 `LOAD/NEXT/LOCK/REVEAL` 是未插入播报时的名义时刻。运行时时刻按第 6 节重算：播报计入下一题后，`LOCK` 前移到下一题播报段起点前 3 秒，`NEXT` 提前到本题播报段起点，因此与编排文件的名义值不同。

### 7.2 命令行

```powershell
python tools\extract_voice_clips.py `
  --source "work\data-backup-20261112-150915\event-offline.mp3" `
  --out-dir "work\voice-extract"

python tools\build_voice_mix.py `
  --source "music\bgm-music.mp3" `
  --voice-dir "work\voice-extract" `
  --script "music\编排.docx" `
  --timeline "backend\data\timeline.json" `
  --out-dir "work\rebuild" `
  --align-audio `
  --voice-anchor next `
  --online-template "backend\data\timeline-online.json"
```

| 参数 | 必填 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `--source` | 是 | — | 纯 BGM 源母带 |
| `--voice-dir` | 是 | — | 12 段播报素材目录，按第 3 节文件名读取 |
| `--script` | 是 | — | 编排文件，提供每题音乐区间与轮末时刻 |
| `--timeline` | 是 | — | 现行 `timeline.json`，提供轮次、题号与动作序列锚点 |
| `--out-dir` | 否 | `work` | 成品音频、时间轴与报告的写入目录 |
| `--voice-anchor` | 否 | `next` | `next` 把播报计入下一题音频窗口；`previous` 计入上一题音频窗口 |
| `--align-audio` | 否 | 关 | 按源音频实际出声点与静音区间重建音乐边界 |
| `--online-template` | 否 | — | 提供时生成线上编排 |
| `--online-audio-file` | 否 | `event-online.mp3` | 线上编排的 `audioFile` 字段 |
| `--online-audio` | 否 | — | 线上音频源文件；启用 `--install` 时替换 `backend/data/event-online.mp3` |
| `--online-out` | 否 | `<out-dir>/timeline-online.next.json` | 线上编排输出路径 |
| `--zero-insert` | 否 | 关 | 强制插入量为 0，只做时间轴自检，不编码音频 |
| `--install` | 否 | 关 | 全部校验通过后备份并替换 `backend/data` 下的线下音频、两份编排；提供 `--online-audio` 时一并替换线上音频 |
| `--gain-db` | 否 | 自动 | 播报统一增益；缺省按第 8 节响度差求解 |

| 退出码 | 含义 |
| ---: | :--- |
| 0 | 成功 |
| 2 | 参数缺失或输入文件不存在 |
| 3 | 编排文件解析失败，或题数与 `timeline.json` 不一致 |
| 4 | 零插入自检与输入的 `timeline.json` 不一致 |
| 5 | 成品编码校验失败（时长、帧数、码率、声道） |
| 6 | 槽位静音或响度校验失败 |
| 7 | `--install` 备份或替换失败 |

非零退出码不写入 `--out-dir` 之外的任何路径，`backend/data` 保持原样。

### 7.3 步骤

1. 解析编排文件，得到每题名义音乐区间、`LOAD/NEXT/LOCK/REVEAL` 与轮末时刻。
2. 检测源音频的静音区间，以静音结束点作为每题音乐起点，以静音起点作为每题音乐终点。
3. 按第 4 节计算槽长、插入量与新的音乐区间。
4. 在静音段内切分源母带，按「音乐段 → 槽前余量静音 → 200 毫秒留白 → 播报段 → 400 毫秒留白 → 下一题音乐」的顺序拼接；轮首槽位按「轮次起点 → 200 毫秒留白 → 开幕段 → 400 毫秒留白 → 本轮音乐」拼接。
5. 第四轮末尾追加谢幕段与 300 毫秒静音。
6. 以单次编码输出 44.1 kHz 立体声 MP3。
7. 按第 6 节重算全部 `atMs`、`audioStartMs`、`audioEndMs` 与轮次区间。
8. 按实际音乐起点生成线上编排，首题 `audioStartMs` 取 0，末题 `audioEndMs` 取音频末尾。
9. 输出对照报告，列出每题的音乐区间、播报区间、插入量与新的动作时刻。

### 7.4 自检

`--zero-insert` 把全部插入量强制为 0 后重新计算，输出必须与输入的 `timeline.json` 一致。

- 输入取未插入播报的编排，例如上一版发布所用的 `timeline.json` 备份；含插入量的现行时间轴不能作为该自检的输入。
- 比较范围：`eventId`、`eventName`、`audioFile`，每轮的 `id`、`name`、`startMs`、`endMs`，以及每轮 `items` 的完整序列。
- `items` 按下标逐项比较 `atMs`、`action`、`questionId`、`audioStartMs`、`audioEndMs`；缺省字段按缺省比较。
- 数值以整数毫秒精确相等，不设容差；JSON 字段顺序与排版不影响结果。
- 任一字段不等即判定失败，输出前 20 条差异（路径、期望值、实际值）并退出 4。
- 通过时报告中 `insertTotal` 为 0，四轮区间与输入一致。

## 8. 编码与音质

| 项目 | 要求 |
| :--- | :--- |
| 采样率 / 声道 | 44100 Hz / 2 |
| 编码 / 码率 | MP3 CBR 192 kbps |
| 时长 | 2429.278 秒 ± 0.1 秒 |
| 体积 | 约 58.3 MB |
| 播报重采样 | 32 kHz 单声道升到 44.1 kHz，双声道等幅复制 |
| 播报增益 | 12 段统一增益，不做逐段归一化；当前成品为 +3.50 dB，播报峰值 −4.50 dBFS |
| 播报响度 | 与音乐段积分响度相差不超过 6 LU；当前音乐段为 −13.20 LUFS |
| 拼接淡化 | 切点两侧各 10 毫秒线性淡化 |

母带由一次编码产出，不对成品做二次转码。切点取每题音乐终点、下一题音乐起点与轮次起点，均位于素材自带静音垫内。

## 9. 校验

### 9.1 启动与接口

```powershell
cd backend
mvn -q -DskipTests compile
Invoke-RestMethod http://localhost:8080/api/events/jisong/state
```

| 项 | 预期 |
| :--- | :--- |
| 启动 | `TimelineStore` 校验通过，两份编排加载成功 |
| 轮次数 | 4 |
| 四轮区间 | 0/562469、562469/1259149、1259149/1871684、1871684/2429278 |
| 每轮首题 `audioStartMs` | 等于本轮 `startMs` |
| 每轮首题 `NEXT.atMs` | 等于本轮 `startMs + 1` |
| 第 2–10 题 `NEXT.atMs` | 等于本题播报段起点 |
| 末轮末题 `audioEndMs` | 2429278 |

### 9.2 槽位核对

对每个播报槽执行：

```powershell
ffmpeg -hide_banner -ss <播报起点/1000> -t <片段时长/1000> -i "backend\data\event-offline.mp3" -af volumedetect -f null NUL
ffmpeg -hide_banner -ss <(槽终点-400)/1000> -t 0.4 -i "backend\data\event-offline.mp3" -af volumedetect -f null NUL
```

- 播报区间内 `max_volume` 高于 −20 dB，表示存在人声。
- 槽末 400 毫秒（谢幕为 300 毫秒）的 `max_volume` 低于 −50 dB，表示播报片段之后为静音。
- 槽前余量与槽后 400 毫秒内不得出现人声；播报结束到下一题音乐起点为 400 毫秒。

### 9.3 音乐核对

对每题音乐起点后 1 秒执行 `volumedetect`，`max_volume` 高于 −20 dB 表示音乐存在且未被播报覆盖。

### 9.4 定位复测

按 [`audio-seek-quality.md`](audio-seek-quality.md) 第 9.3 节方法，对 40 题的 `answerStartMs` 逐题定位，首次出声时刻与素材内容相差不超过 0.5 秒。

### 9.5 试听

逐轮试听：轮首播报、9 处题间、轮末致辞；确认播报完整、无截断、无音乐混入，且播报紧邻下一题音乐。

## 10. 现场表现

| 场景 | 表现 |
| :--- | :--- |
| 第一轮开始 | 主持人点击开始后首题在 1 毫秒上屏，同时播放开幕播报，播报结束后进入首题音乐 |
| 第二至四轮开始 | 主持人点击开始后首题在本轮起点后 1 毫秒上屏，同时播放本轮轮首播报 |
| 每题结束 | 音乐结束后先经过槽前余量静音；下一题上屏时播放本题间播报，播报结束后保留 400 毫秒静音进入下一题音乐 |
| 每轮结束 | 第 10 题播报在 `FINISH` 前 400 毫秒结束；第四轮随后播放 2.21 秒谢幕 |
| 音量控制 | 主持人音量滑杆同时作用于音乐与播报 |

线上模式播放纯 BGM 对象，不含本节所述播报；线上音频与推进规则见 [`dual-master-audio.md`](dual-master-audio.md)。

## 11. 已知约束

1. 播报与音乐的相对音量在生成阶段固定，现场只能整体调节。
2. 台本内容、片段时长或槽位规则变化时，需重制线下母带与 `timeline.json`，并核对 `timeline-online.json` 的题目序列与线上题集。
3. 线下母带总长随生成结果变化；线上题集版本只由 `timeline-online.json` 决定。
4. 线下母带比纯 BGM 母带长 184.787 秒，体积增加约 4.4 MB；线上流量不受影响。
5. 播报素材为 32 kHz 单声道，升采样不增加信息量；播报段的频响上限为 16 kHz。
6. 线下主持人提前推进时，本题剩余音频（含未播完的播报）被跳过。
7. 播报素材来自含播报的旧线下母带；更换 BGM 不改变播报素材，重制母带时需要保留 `work/voice-extract` 或重新提供原始播报素材。
