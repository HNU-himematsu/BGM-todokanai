# 主持人播报与完整音频合成规范

## 1. 文档用途

本文定义主持人播报（绫地宁宁）12 段语音接入猜歌活动的规则：素材清单、播报在完整音频中的落点与槽位长度、四轮对位表、轮首播报槽位、时间轴重算规则、生成流程、校验方法与现场表现。

含播报母带只服务线下模式；线上模式的纯 BGM 母带与双编排配置见 [`dual-master-audio.md`](dual-master-audio.md)。

读者对象为素材制作方、数据生成者与现场执行者。编排文件的通用契约见 [`timeline-spec.md`](timeline-spec.md)，活动的题库与轮次数值见 [`jisong-event-integration.md`](jisong-event-integration.md)，编码与定位指标见 [`audio-seek-quality.md`](audio-seek-quality.md)。

## 2. 接入形态

播报以离线合成方式进入线下母带，每台设备运行期只有一个音频文件、一个播放器。

- 含播报母带只服务线下主持人控制台，对象为 `bgm/event-offline.mp3`；线上参与者播放纯 BGM 对象，内容不含播报。
- `backend/data/event-demo.mp3` 是单母带中间产物，`backend/data/event-offline.mp3` 是四轮成品；上传到 OSS 后，部署服务器不保存该文件。
- 播报片段只在生成阶段使用，不放入 `backend/data`，不通过接口提供，不参与运行期加载。
- 播报槽位落在本题音乐终点之后的静音段内；播报结束到下一题音乐之间至少保留 400 毫秒静音。

实时叠加要求每台设备同时播放两个媒体元素。移动端浏览器的并发播放策略、时钟漂移，以及线上的跳题、切后台暂停与进度恢复，都会让两个元素失去同步。单文件合成让上述行为直接沿用现有实现。

## 4. 对位规则

| 项目 | 规则 |
| :--- | :--- |
| 槽位起点 | 本题音乐终点 |
| 前置留白 | 200 毫秒 |
| 尾部留白 | 400 毫秒 |
| 槽长 | 片段时长 + 600 毫秒 |
| 新空档 | `max(原空档, 槽长)` |
| 插入量 | 新空档 − 原空档 |
| 槽后余量 | 新空档 − 槽长 |
| 播报结束到下一题音乐 | 400 毫秒 + 槽后余量 |

- 原空档取编排文件的「本题音乐片段结束」到「下一题音乐片段开始」之间的时长；每轮第 10 题取到本轮 `endMs`。
- 装得下的空档保持原长，播报后用余量静音补齐；装不下的空档按槽长加长，后续音乐整体后移。
- 开幕置于文件起点，槽长 33535 毫秒（32935 + 600）。第一轮 `startMs` 取 0，第 1 题 `audioStartMs` 取 0，音频窗口包含开幕段。
- 第二至四轮轮首槽位取开幕段整段（0–33535 毫秒），槽起点为本轮 `startMs`，无前置留白，槽长 33535 毫秒；本轮首题音乐起点为 `startMs + 33535`，首题 `audioStartMs` 取本轮 `startMs`，音频窗口包含轮首播报段。
- 谢幕追加在第四轮末尾，是槽长规则的例外：片段之后没有下一题音乐，只保留 300 毫秒尾部留白，槽长 2210 毫秒（1910 + 300）。第四轮 `endMs` 随之后移，母带以该段静音收尾。

## 6. 时间轴重算

### 6.1 锚定规则

| 条目 | 锚点 | 取值 |
| :--- | :--- | :--- |
| `LOAD.atMs` | 本题音乐起点 | −1000；本轮首题取音乐起点 |
| `NEXT.atMs` | 本题音乐起点 | 0；本轮首题取音乐起点 +1 |
| `LOCK.atMs` | 本题音乐终点 | 保留每题原有的 `LOCK − 音乐终点` 偏移（7000、9000 或 37000） |
| `REVEAL.atMs` | 本题音乐终点 | `LOCK` 后 1000 |
| `FINISH.atMs` | 轮末 | 0 |
| `audioStartMs` | 本题音乐起点 | 每轮首题取本轮 `startMs`，其余取音乐起点 |
| `audioEndMs` | 下一题音乐起点 | 轮末题取本轮 `endMs` |

`LOCK` 与 `REVEAL` 锚定在音乐终点，每题「上屏到锁卷」的作答窗口长度与编排一致，不因播报插入而延长。`LOAD` 与 `NEXT` 锚定在音乐起点，随插入量同步后移，题目与音乐保持对齐。

### 6.2 轮次区间

| id | name | startMs | endMs |
| :--- | :--- | ---: | ---: |
| `round-1` | 第一轮 | 0 | 562355 |
| `round-2` | 第二轮 | 562355 | 1341690 |
| `round-3` | 第三轮 | 1341690 | 2054605 |
| `round-4` | 第四轮 | 2054605 | 2780110 |

四轮插入量依次为 61355（含开幕 33535）、46335、41915、37505，其中第二至四轮插入量包含轮首播报 33535 毫秒。母带总长 2780110 毫秒，即 46 分 20.110 秒。

40 题的绝对时刻见 [`jisong-event-integration.md`](jisong-event-integration.md) 第 5.6 节。

### 6.3 数据不变量

在 [`timeline-spec.md`](timeline-spec.md) 第 8 节之外，本活动的数据同时满足：

1. 每个播报片段的结束时刻与下一题音乐起点之间不少于 400 毫秒。
2. 每轮第 10 题的播报片段早于 `FINISH` 时刻结束。
3. 谢幕片段结束后保留 300 毫秒静音，母带以静音收尾。
4. 末题 `audioEndMs` 等于母带总长 2780110。
5. 相邻题的 `audioEndMs` 与下一题 `audioStartMs` 相等，第一题 `audioStartMs` 为 0。

## 7. 生成流程

### 7.1 工具与输入

生成器为 `tools/build_voice_mix.py`，输入四项：

- `music/编排.docx`：40 题的音乐片段起止与四轮时长。
- `music/0d00/`：12 段播报素材。
- `music/bgm-music.mp3`：题集混拼母带。
- `backend/data/timeline.json`：动作条目与题号引用。

### 7.2 命令行

```powershell
python tools\build_voice_mix.py `
  --source "music\bgm-music.mp3" `
  --voice-dir "music\0d00" `
  --script "music\编排.docx" `
  --timeline "backend\data\timeline.json" `
  --out-dir "work"
```

| 参数 | 必填 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `--source` | 是 | — | 题集混拼源母带 |
| `--voice-dir` | 是 | — | 12 段播报素材目录，按第 3 节文件名读取 |
| `--script` | 是 | — | 编排文件，提供每题音乐区间与轮末时刻 |
| `--timeline` | 是 | — | 现行 `timeline.json`，提供题号、动作序列与锚点偏移 |
| `--out-dir` | 否 | `work` | 成品音频、新时间轴与报告的写入目录 |
| `--zero-insert` | 否 | 关 | 强制插入量为 0，只做时间轴自检，不编码音频 |
| `--install` | 否 | 关 | 全部校验通过后备份并替换 `backend/data` 下的两个文件 |
| `--gain-db` | 否 | 自动 | 播报统一增益；缺省按第 8 节响度差求解 |

| 退出码 | 含义 |
| ---: | :--- |
| 0 | 成功 |
| 2 | 参数缺失或输入文件不存在 |
| 3 | 编排文件解析失败，或题数与 `timeline.json` 不一致 |
| 4 | 零插入自检与输入的 `timeline.json` 不一致 |
| 5 | 成品编码校验失败（时长、帧数、码率、声道） |
| 6 | 槽位静音或响度校验失败 |
| 7 | `--install` 备份或替换失败 |

非零退出码不写入 `--out-dir` 之外的任何路径，`backend/data` 保持原样。

### 7.3 步骤

1. 解析编排文件，得到每题音乐区间与轮末时刻。
2. 按第 4 节计算槽长、插入量与新的音乐区间。
3. 在静音段内切分源母带，按「音乐段 → 200 毫秒留白 → 播报段 → 400 毫秒留白 → 余量静音」的顺序拼接；轮首槽位按「轮次起点 → 开幕段整段 → 本轮音乐」拼接，无前置留白。
4. 以单次编码输出 44.1 kHz 立体声 MP3。
5. 按第 6 节重算全部 `atMs`、`audioStartMs`、`audioEndMs` 与轮次区间。
6. 输出对照报告，列出每题的音乐区间、槽位、插入量与新的动作时刻。

### 7.4 自检

`--zero-insert` 把全部插入量强制为 0 后重新计算，输出必须与输入的 `timeline.json` 一致。

- 输入取未插入播报的 `timeline.json`：首次生成时为 `backend/data/timeline.json` 的原文件，重跑时为 `backend/data-backup/timeline.json`。含插入量的成品时间轴不能作为该自检的输入。
- 比较范围：`eventId`、`eventName`、`audioFile`，每轮的 `id`、`name`、`startMs`、`endMs`，以及每轮 `items` 的完整序列。
- `items` 按下标逐项比较 `atMs`、`action`、`questionId`、`audioStartMs`、`audioEndMs`；缺省字段按缺省比较。
- 数值以整数毫秒精确相等，不设容差；JSON 字段顺序与排版不影响结果。
- 任一字段不等即判定失败，输出前 20 条差异（路径、期望值、实际值）并退出 4。
- 通过时报告中 `insertTotal` 为 0，四轮区间与输入一致。

### 7.5 产物

| 产物 | 位置 | 说明 |
| :--- | :--- | :--- |
| 完整音频 | `<out-dir>/event-offline.mp3` | 含题间播报与四轮轮首播报，2780110 毫秒 |

## 8. 编码与音质

| 项目 | 要求 |
| :--- | :--- |
| 采样率 / 声道 | 44100 Hz / 2 |
| 编码 / 码率 | MP3 CBR 192 kbps |
| 时长 | 2780.110 秒 ± 0.1 秒 |
| 体积 | 约 66.7 MB |
| 播报重采样 | 32 kHz 单声道升到 44.1 kHz，双声道等幅复制 |
| 播报增益 | 12 段统一增益，不做逐段归一化；峰值不超过 −1.0 dBFS |
| 播报响度 | 与音乐段积分响度相差不超过 6 LU |
| 拼接淡化 | 切点两侧各 10 毫秒线性淡化 |

母带由一次编码产出，不对成品做二次转码。切点取每题音乐终点与轮次起点，均位于素材自带静音垫内。

## 9. 校验

### 9.1 启动与接口

```powershell
cd backend
mvn -q -DskipTests compile
Invoke-RestMethod http://localhost:8080/api/events/demo/state
```

| 项 | 预期 |
| :--- | :--- |
| 启动 | `TimelineStore` 校验通过，两份编排加载成功 |
| 轮次数 | 4 |
| 四轮区间 | 0/562355、562355/1341690、1341690/2054605、2054605/2780110 |
| 每轮首题 `audioStartMs` | 等于本轮 `startMs` |
| 每轮首题 `LOAD.atMs` | 等于本轮 `startMs + 33535` |
| 末轮末题 `audioEndMs` | 2780110 |

### 9.2 槽位核对

对每个播报槽执行：

```powershell
ffmpeg -hide_banner -ss <槽起点> -t <槽长/1000> -i "backend\data\event-offline.mp3" -af volumedetect -f null NUL
ffmpeg -hide_banner -ss <(槽起点+槽长-400)/1000> -t 0.4 -i "backend\data\event-offline.mp3" -af volumedetect -f null NUL
```

- 槽内 `max_volume` 高于 −20 dB，表示存在人声。
- 槽内末尾 600 毫秒（轮首槽）或 400 毫秒（题间槽）的 `max_volume` 低于 −50 dB，表示播报片段之后为静音。插入量大于 0 的槽没有槽后余量，尾部静音只能落在槽内。
- 槽结束后到下一题音乐起点之间不得出现人声。

### 9.3 音乐核对

对每题音乐起点后 1 秒执行 `volumedetect`，`max_volume` 高于 −20 dB 表示音乐存在且未被播报覆盖。

### 9.4 定位复测

按 [`audio-seek-quality.md`](audio-seek-quality.md) 第 9.3 节方法，对 40 题的 `answerStartMs` 逐题定位，首次出声时刻与素材内容相差不超过 0.5 秒。

### 9.5 试听

逐轮试听：轮首播报、9 处题间、轮末致辞；确认播报完整、无截断、无音乐混入。

| 第一轮开始 | 主持人点击开始后先播放开幕播报，首题在 33536 毫秒上屏 |
| 第二至四轮开始 | 主持人点击开始后先播放本轮轮首播报（第一轮开幕段），随后进入本轮第 1 题音乐 |
| 每题结束 | 音乐结束后播放题间播报，播报结束后至少保留 400 毫秒静音再进入下一题音乐 |
| 每轮结束 | 第 10 题播报在 `FINISH` 前结束：第一轮的播报槽占满轮末空档，片段后保留 0.4 秒；第二至四轮播报槽后另有 24.74 秒静音 |
| 音量控制 | 主持人音量滑杆同时作用于音乐与播报 |

线上模式播放纯 BGM 对象，不含本节所述播报；线上音频与推进规则见 [`dual-master-audio.md`](dual-master-audio.md)。

## 11. 已知约束

1. 播报与音乐的相对音量在生成阶段固定，现场只能整体调节。
2. 台本内容、片段时长或槽位规则变化时，需重制线下母带与 `timeline.json`，并核对 `timeline-online.json` 的题目序列与线上题集。
3. 线下母带总长随生成结果变化；线上题集版本只由 `timeline-online.json` 决定。
4. 线下母带比纯 BGM 母带长 187.1 秒，体积增加约 4.2 MB；线上流量不受影响。
5. 播报素材为 32 kHz 单声道，升采样不增加信息量；播报段的频响上限为 16 kHz。
6. 线上推进由用户点击触发，提前推进时本题剩余音频（含未播完的播报）被跳过。
