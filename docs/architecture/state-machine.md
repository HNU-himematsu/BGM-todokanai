# 活动生命周期状态机与调度机制

## 1. 状态枚举定义 (`ActivityStatus`)

系统包含 4 种活动状态，每个状态具有明确的准入条件、操作权限与时效限制：

```text
       ┌───────────┐
       │  WAITING  │ <────────────────────────────────┐
       └─────┬─────┘                                  │
             │ startQuestion() / auto-run             │
             ▼                                        │
      ┌─────────────┐                                 │
  ┌─> │  ANSWERING  │ ──┐                             │
  │   └─────────────┘   │ 20s 倒计时结束              │
  │                     │ 或 主持人 endAnswer()       │
  │   ┌─────────────────▼┐                            │
  │   │ ANSWER_REVEALED  │                            │
  │   └────────┬─────────┘                            │
  │            │                                      │
  │ 还有后续题 │ 6s 揭晓结束                          │
  └────────────┤ 或 主持人 nextQuestion()             │
               │                                      │
               │ 最后一题结束                         │ reset()
               ▼                                      │
        ┌────────────┐                                │
        │  FINISHED  │ ───────────────────────────────┘
        └────────────┘
```

1. **`WAITING`（就绪等待）**：
   - 活动已初始化或已重置。
   - 允许参与者通过手机端扫码加入房间并登记昵称。
   - 题目内容对参与者不可见。
2. **`ANSWERING`（作答进行中）**：
   - 当前题目开放作答，下发脱敏后的题目视图（不含正确答案与解析）。
   - 服务端启动 20 秒倒计时（`deadlineEpochMs`）。
   - 参与者提交单选答案，服务端记录选择与提交耗时。
3. **`ANSWER_REVEALED`（答案与解析揭晓）**：
   - 锁定该题提交通道，拒绝后续答案请求。
   - 下发正确答案与解析说明。
   - 揭晓界面停留 6 秒，供现场参与者核对。
4. **`FINISHED`（活动结束与归档）**：
   - 所有题目（共 6 题）作答完毕。
   - 系统计算各参与者总分与总耗时，执行最终竞速排序。
   - 触发排行榜持久化，归档数据至 `leaderboards.json` 与 `leaderboard_summary.txt`。

## 2. 自动化调度引擎实现

服务端采用 `ScheduledExecutorService` 实现独立守护线程（线程名 `bgm-scheduler`）的事件调度：

### 2.1 倒计时与超时处理
- **作答阶段计时**：进入 `ANSWERING` 状态时，调度器设定 20 秒延迟任务 `handleQuestionTimeout`。若达到 20 秒未收到提前揭晓指令，服务端自动将状态变更为 `ANSWER_REVEALED` 并向全网广播。
- **揭晓阶段计时**：进入 `ANSWER_REVEALED` 状态时，调度器设定 6 秒延迟任务 `handleRevealTimeout`。若达到 6 秒，系统自动判定当前题号：
  - 若 `currentQuestionIndex + 1 < totalQuestions`：自动开启下一题进入 `ANSWERING` 状态；
  - 若已是最后一题：自动结束本轮活动进入 `FINISHED` 状态并写入存储。

### 2.2 手动干预与调度器协作
- 主持人执行任何主动状态变更指令（如提前结束作答、提前切题、暂停轮转等）时，服务端优先调用 `cancelTimer` 取消挂起中的 `ScheduledFuture` 任务，防止定时任务与人工指令发生状态覆盖。
- 主持人调用暂停接口时，系统注销当前定时任务，状态保持在当前画面；调用恢复接口时，系统根据当前状态重新计算剩余时长或直接启动后续定时调度。
