# 活动生命周期状态机与时间轴调度机制

## 1. 状态枚举定义 (`ActivityStatus`)

系统包含 5 种活动状态，覆盖从就绪等待到结算归档的完整生命周期：

```text
WAITING ──NEXT──> ANSWERING ──LOCK──> ANSWER_LOCKED ──REVEAL──> ANSWER_REVEALED
   ▲                                                                  │
   │                                              后续题 NEXT（回到 ANSWERING）
   │                                                                  │
   │                                               最后一题 FINISH      ▼
   └──────────── 切换轮次 / reset() ────────────── FINISHED
```

1. **`WAITING`（就绪等待）**：
   - 活动初始化、重置或切换轮次后进入本状态。
   - 允许参与者随时加入房间并登记昵称。
   - 题目内容对参与者不可见。
2. **`ANSWERING`（作答进行中）**：
   - 由 `NEXT` 动作开启当前题目，下发脱敏后的题目视图（不含正确答案与解析）。
   - 参与者提交单选答案，服务端记录选择与提交耗时。
   - 作答通道的关闭时刻完全由编排中的 `LOCK` 动作决定，系统不设固定时限。
3. **`ANSWER_LOCKED`（锁卷）**：
   - 锁定该题提交通道，拒绝后续答案请求。
   - 不公布正确答案与解析，参与者界面呈现已锁卷提示。
   - 锁卷瞬间为尚未提交的玩家按参与时长补记耗时。
4. **`ANSWER_REVEALED`（答案与解析揭晓）**：
   - 下发正确答案与解析说明。
   - 揭晓画面持续到下一题的 `NEXT` 动作执行，供现场参与者核对。
5. **`FINISHED`（活动结束与归档）**：
   - 由编排中的 `FINISH` 动作触发，计算总分与总耗时并执行最终竞速排序。
   - 归档数据至 `leaderboards.json` 与 `leaderboard_summary.txt`。
   - 拒绝新玩家加入；到达轮次结束标记时时间轴暂停，本状态保持不变。

## 2. 轮次与时间轴

### 2.1 轮次定义
- 编排文件定义一个完整音频内的多个轮次，每个轮次由音频绝对时间区间 `[startMs, endMs]` 与动作条目列表构成。
- 轮次之间互不重叠；轮次可以被重复选择播放，用于接待不同批次参与者。
- 主持人控制台在未开始、已暂停或已结束时允许切换轮次；切换操作重置房间（清空在线玩家）并回退到 `WAITING` 状态。

### 2.2 零点与触发时刻
- 主持人控制台将音频定位到当前轮次开始标记后开始播放，同时调用启动接口。
- 服务端以启动接口的接收时刻作为本轮零点 `T0`。
- 动作条目的实际触发时刻按下式换算：

```text
触发时刻 = T0 + (atMs − startMs)
```

### 2.3 轮次结束标记
- 调度器为当前轮次的结束标记挂载独立延时任务。
- 到达结束标记时，服务端停止时间轴并广播 `ROUND_ENDED`，控制台据此暂停音频播放。
- 结束标记仅负责暂停轮次，结算与归档由编排中的 `FINISH` 动作承担。

## 3. 单一动作定义

| 动作 | 语义 | 状态流转 | 广播事件 |
| :--- | :--- | :--- | :--- |
| `LOAD` | 预加载题目内容（含音频段起止标记）至待上屏槽位，不改变参与者屏幕 | 状态保持不变 | 无 |
| `NEXT` | 将待上屏内容上屏显示、题目序号 +1、开放作答通道 | `WAITING` / `ANSWER_REVEALED` → `ANSWERING` | `QUESTION_STARTED` |
| `LOCK` | 关闭作答通道并补记缺席耗时，不公布答案 | `ANSWERING` → `ANSWER_LOCKED` | `ANSWER_LOCKED` |
| `REVEAL` | 公布正确答案与解析 | `ANSWER_LOCKED` → `ANSWER_REVEALED` | `ANSWER_REVEALED` |
| `FINISH` | 结算本轮成绩并归档榜单 | 任意进行态 → `FINISHED` | `ACTIVITY_FINISHED` |

动作执行前的状态守卫规则：
- `NEXT` 要求当前处于 `WAITING` 或 `ANSWER_REVEALED` 状态，且待上屏槽位存在已预加载内容；不满足时跳过执行。
- `LOCK` 在非 `ANSWERING` 状态下跳过执行。
- `REVEAL` 在非 `ANSWER_LOCKED` 状态下跳过执行。
- `FINISH` 执行后，当前轮次其余待执行条目均跳过执行。
- 编排加载阶段校验条目序列的合法性，拦截顺序错误的编排文件。

## 4. 标准题目序列

```text
LOAD → NEXT → LOCK → REVEAL → LOAD → NEXT → LOCK → REVEAL → … → FINISH
```

- 题目序号在 `NEXT` 执行时递增，从 1 开始。
- `REVEAL` 至下一题 `NEXT` 之间，参与者屏幕保持上一题揭晓内容。
- 每题的作答窗口时长、音频段起止与动作时刻均由编排人员在同一份编排文件中定义。

## 5. 自动化调度引擎实现

服务端采用 `ScheduledExecutorService` 实现独立守护线程（线程名 `bgm-scheduler`）的时间轴调度：

### 5.1 条目调度
- 启动轮次时，调度器为当前轮次的所有条目与结束标记分别挂载一次性延迟任务。
- 每个任务执行前校验目标状态与轮次归属，避免过期任务影响当前轮次。

### 5.2 暂停与恢复
- 主持人执行暂停指令时，服务端注销全部挂起任务并记录暂停锚点，状态保持在当前界面。
- 主持人执行恢复指令时，服务端按各条目的剩余时长重新挂载任务，并以暂停时长平移轮次结束标记的触发时刻。
- 恢复后，时间轴继续执行剩余条目。

### 5.3 手动干预与调度器协作
- 主持人可执行手动锁卷、手动揭晓、手动上屏下一题、重置与切换轮次等指令，作为时间轴自动执行之外的兜底手段。
- 手动指令执行前先取消相关挂起任务；已被手动满足语义的时间轴条目在触发时因状态守卫而空转跳过，不对现场造成影响。

## 6. 作答窗口与耗时统计

### 6.1 作答窗口
- 单题作答窗口等于该题 `NEXT` 与 `LOCK` 两个动作的时间间隔，由编排定义，系统不设固定时限。
- 锁卷是作答通道的唯一截止方式。

### 6.2 耗时计算
- **单题有效耗时**：参与者提交时刻与本题 `NEXT` 时刻的毫秒差值。
- **缺席补记**：`LOCK` 执行时，尚未提交的玩家按 `LOCK 时刻 − max(本题 NEXT 时刻, 加入时刻)` 补记耗时。
- **中途加入边界**：玩家加入前已锁卷的题目不产生耗时记录。
- **累计总耗时**：本轮所有题目耗时之和为参与者的 `totalDurationMs`。

### 6.3 计分
- 单题作答正确得 10 分；作答错误或锁卷时仍未提交得 0 分。
- 排行榜按得分降序、总耗时升序、加入时间升序、昵称升序依次仲裁。
