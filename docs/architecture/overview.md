# 系统总体架构设计

## 1. 系统定位与核心特征

本系统用于展位与活动现场的多人在线互动猜歌，具备以下核心技术特征：
- **单音频编排驱动**：现场播放一个完整音频文件，服务端依据与音频对应的编排 JSON 执行动作与内容下发，时间编排、题目内容与动作语义全部由数据定义，无需修改代码。
- **免数据库依赖**：采用内存状态机结合本地文件系统（JSON / TXT / 音频文件）完成状态维护、内容加载与排行榜归档，降低部署与维护门槛。
- **弱网适应能力**：基于 STOMP WebSocket 实现单向轻量广播，客户端支持断线自动重连与状态同步，适应高人流现场的基站网络抖动。
- **多轮次接待**：编排文件定义多个轮次，控制台可切换轮次，到达轮次结束标记自动暂停，适配不同批次参与者的循环接待。
- **竞速排行榜仲裁**：记录毫秒级作答耗时，在相同得分情况下依据答题用时实施精确排名。

## 3. 逻辑分层架构

```text
┌────────────────────────────────────────────────────────┐
│                      表现层 (Vue 3)                     │
│  - 参与者手机端 (JoinView / PlayView)                  │
│  - 主持人控制台 (HostView：音频播放、轮次切换、状态调度) │
└───────────────▲────────────────────────▲───────────────┘
                │ HTTP REST              │ WebSocket (STOMP)
                ▼                        ▼
┌────────────────────────────────────────────────────────┐
│                   通讯层 (Spring MVC / STOMP)          │
│  - REST 控制器: EventController / HostController       │
│  - WebSocket 消息代理: /topic/events/{eventId}         │
└───────────────────────────────┬────────────────────────┘
                                │
┌───────────────────────────────▼────────────────────────┐
│                      业务层 (Spring Service)           │
│  - ActivityService: 状态机、时间轴调度、答题校验、竞速 │
│  - TimelineStore: 编排加载、轮次解析、编排合法性校验   │
│  - LeaderboardStore: 榜单归档、跨轮次汇总、等宽排版    │
│  - HostAuthService: 主持人认证与令牌管理               │
└───────────────────────────────┬────────────────────────┘
                                │
┌───────────────────────────────▼────────────────────────┐
│                     持久化层 (本地文件系统)             │
│  - data/timeline.json: 轮次、动作时间轴与题目引用      │
│  - data/questions.json: 题干、选项、答案与解析          │
│  - data/<audioFile>: 单文件完整音频（轮次为其中区段）  │
│  - data/leaderboards.json: 历史轮次结算快照           │
│  - data/leaderboard_summary.txt: 全场总榜与去重奖品榜  │
└────────────────────────────────────────────────────────┘
```

## 4. 关键组件与职责说明

1. **`ActivityService`**：系统核心调度引擎，维护活动内存实例 `Activity`，管理玩家连接、待上屏内容、题目进度、时间轴任务、轮次切换及同分竞速排序。
2. **`TimelineStore`**：加载并解析本地 `timeline.json` 与 `questions.json`，关联题目编号，校验轮次区间、动作序列与题库数据，向调度引擎提供轮次清单与条目数据。
3. **`LeaderboardStore`**：负责活动结算数据的持久化。提供同步写入机制，保障 `leaderboards.json` 数据一致性，并自动刷新生成包含中英文字符等宽对齐的 `leaderboard_summary.txt`。
4. **`HostAuthService`**：管理主持人控制权限，校验 `X-Host-Token` 请求头，确保管理指令的安全受控。
