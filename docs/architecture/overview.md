# 系统总体架构设计

## 1. 系统定位与核心特征

系统用于社团活动中的猜歌互动，同时提供线上独立答题与线下现场答题两种参与方式。

- **双模式入口**：网页默认进入线上模式；现场二维码通过 `/offline` 路径进入线下模式，`?mode=offline` 查询参数等效。线下登记页提供线上模式入口。
- **共用题库、分离音频**：线上与线下读取同一份 `questions.json`；线上使用 `timeline-online.json` 与纯 BGM 母带，线下使用 `timeline.json` 与含播报母带，两份编排的题目序列一致。
- **双编排驱动**：线下模式由主持人控制轮次音频；服务端依据 `timeline.json` 自动执行题目上屏、锁卷、揭晓与结算。线上题集由 `timeline-online.json` 生成。
- **线上本地推进**：线上模式把线上编排中的题目按顺序拉平，忽略轮次边界，由浏览器按音频与题目级时间标记自动推进；当前题已选答案后可按顺序进入下一题。答题进度保存在浏览器本地。
- **免数据库依赖**：采用内存状态机结合本地文件系统（JSON / TXT）与 OSS 音频对象完成状态维护、内容加载与榜单归档。
- **弱网适应能力**：线下模式通过 STOMP WebSocket 广播状态变更；线上模式以 REST 拉取题集与提交预览/锁定，不依赖实时广播。
- **三类榜单**：线下轮次榜用于现场评奖；线上积分榜保存线上锁定成绩；总榜合并线下各轮最佳成绩与线上锁定成绩。

│  - 主持人控制台 (HostView：轮次、音频、时间轴、榜单)    │

                ▼                        ▼

                                │
┌───────────────────────────────▼────────────────────────┐

│  - ActivityService: 线下状态机、时间轴、作答、结算     │

│  - TimelineStore: 题库/编排加载、线上题集、校验        │
│  - LeaderboardStore: 线下快照、线上记录、总榜、导出    │

│  - data/questions.json: 题干、选项、答案与解析          │

## 4. 关键组件与职责

1. **`ActivityService`**：维护线下活动内存实例 `Activity`，管理玩家连接、待上屏内容、题目进度、时间轴任务、轮次切换及同分竞速排序。
2. **`OnlineAttemptService`**：提供线上题集读取、预览分计算、锁定写入、线上榜查询与总榜查询。线上答题进度由浏览器保存，服务端不保存进行中的线上 attempt。
3. **`TimelineStore`**：加载并解析两份编排与 `questions.json`，交叉校验题目序列，生成线上题集与 `questionSetVersion`，校验轮次区间、动作序列、题目音频片段与题库覆盖。
4. **`LeaderboardStore`**：持久化线下轮次快照与线上锁定记录，聚合总榜，生成等宽文本总结。
5. **`HostAuthService`**：管理主持人控制权限，校验 `X-Host-Token` 请求头。

## 5. 模式边界

| 能力 | 线上模式 | 线下模式 |
| :--- | :--- | :--- |
| 入口 | `/` | `/?mode=offline` |
| 题目范围 | 题库全部题目，按线上编排拉平去重 | 主持人选中的轮次 |
| 推进方式 | 浏览器按音频与题目级标记自动推进；已答题目可按顺序进入下一题 | 服务端按轮次时间轴调度 |
| 音频播放 | 参与者设备播放纯 BGM 母带 | 主持人控制台播放含播报母带的轮次区间 |
| 答案揭晓 | 不揭晓 | `REVEAL` 公布答案、作品名与出题人 |
| 进度保存 | 浏览器 `localStorage` | 服务端内存 + 线下玩家会话 |
| 结算 | 预览分后重试或锁定 | `FINISH` 自动结算本轮 |
| 榜单 | 线上积分榜 + 总榜 | 线下轮次榜 + 总榜 |

## 6. 数据与一致性

- 题库、编排与音频为只读输入，服务启动时加载并校验。
- 线下轮次结算写入 `leaderboards.json`；线上锁定写入 `online_leaderboard.json`。
- 总榜在请求时按 `participantId` 聚合，不单独持久化排行结果。
- 文本总结在每次线下结算或线上锁定后刷新。
- 线上预览不产生持久化副作用；线上锁定与线下结算写入使用同步保护。
