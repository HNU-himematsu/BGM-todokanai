# 故障排查手册与现场应急预案

## 1. 网络与实时通信故障

### 1.1 手机端无法接收状态广播（界面无剩余时间条或无法切题）
- **现象描述**：主持人控制台已进入下一题，但部分或全部参与者手机端仍停留在上一题。
- **可能原因**：现场手机基站拥塞导致 WebSocket 长连接中断，或反向代理未正确透传 WebSocket 标头。
- **排查与处置**：
  1. 参与者在手机浏览器中下拉刷新页面，页面在重新加载时自动调用 `/api/events/{id}/state` 同步服务端最新快照。
  2. 若全员均无法收到推送，检查 Nginx 配置中 `location /ws` 是否配置了 `Upgrade $http_upgrade` 与 `Connection "upgrade"` 头。

### 1.2 穿透域名访问超时或报 502 Bad Gateway
- **现象描述**：扫描二维码后提示无法连接服务器或返回 502。
- **可能原因**：Spring Boot 后端进程意外终止，或 Cloudflare Tunnel 进程异常退出。
- **排查与处置**：
  1. 检查后端控制台窗口，确认 Java 进程是否正常存活并在 8080 端口监听。
  2. 检查 `cloudflared.exe` 终端窗口，若出现断开报错，重新执行命令拉起隧道并同步更新现场展示的二维码。

## 2. 时间轴与场控流程故障

### 2.1 到达动作时刻后系统未推进
- **现象描述**：音频已播放到题目节点，但题目未上屏、未锁卷或未揭晓。
- **可能原因**：时间轴处于暂停状态，或轮次已到达结束标记并进入 `ROUND_ENDED`，或编排条目因状态守卫被跳过。
- **排查与处置**：
  1. 主持人检查控制台时间轴状态，点击「恢复」继续推进。
  2. 若已到达轮次结束标记，切换轮次或重置后重新开始。
  3. 必要时点击「锁卷」「揭晓答案」「下一题」按钮执行手动兜底。

### 2.2 现场音频节奏失误（播放被打断或错位）
- **处置方案**：
  1. 主持人立即点击控制台「暂停」按钮，时间轴与音频同步冻结。
  2. 确认音箱与播放环境恢复正常后点击「恢复」，系统按剩余时长继续推进编排，无需重新开始轮次。
  3. 若偏差过大，切换轮次或重置后重新播放本轮音频。

### 2.3 控制台音频无法播放或与题目不同步
- **排查与处置**：
  1. 确认 `backend/data/` 下音频文件名与编排文件 `audioFile` 字段一致。
  2. 浏览器自动播放策略要求首次播放必须由用户点击触发，主持人需通过控制台「开始播放」按钮启动。
  3. 若音频与时间轴偏差超过半首歌，暂停并切换轮次重开本轮。

## 3. 数据持久化与灾难恢复

### 3.1 后端服务意外退出或崩溃
- **数据影响范围**：
  - 历史轮次结算数据均已持久化至 `backend/data/leaderboards.json`，历史排行榜数据不受影响。
  - 当前进行中的未完成单轮数据会随进程丢失。
- **恢复步骤**：
  1. 重新启动后端服务：`mvn spring-boot:run`。
  2. 启动后，`TimelineStore` 自动加载编排文件，`LeaderboardStore` 自动校验并加载历史快照文件。
  3. 主持人点击控制台「重置活动」或重新选择轮次，组织现场同学重新开局。

### 3.2 启动失败并提示编排校验错误
- **现象描述**：后端启动日志输出编排文件的问题条目位置并拒绝启动。
- **排查与处置**：
  1. 按日志定位 `timeline.json` 中对应轮次或条目，核对时间递增、`LOAD` 与 `NEXT` 配对、题目字段等约束。
  2. 修正后重新启动服务。

### 3.3 离线查看与导出排行榜
若现场无法访问网页端排行榜，可直接在项目根目录运行 Python 脚本重新导出纯文本榜单：
```bash
python parse_leaderboard.py
```
生成的 `backend/data/leaderboard_summary.txt` 可直接使用 Windows 记事本打开并打印或核对发奖。
