# 故障排查手册与现场应急预案

## 1. 快速判断

| 现象 | 优先检查 |
| :--- | :--- |
| 根地址进入线下页面 | 地址是否带 `/offline` 路径或 `mode=offline` 参数。 |
| 线下二维码进入线上页面 | 二维码是否为 `{publicBaseUrl}/?mode=offline`。 |
| 线上无法开始 | 题库、编排、音频、浏览器自动播放策略、服务端健康状态。 |
| 线上进度丢失 | 域名、隐私模式、站点数据清理、题集版本。 |
| 线上「下一题」不可用或跳转异常 | 是否已选答案、是否最后一题、音频元数据、下一题 `answerStartMs`、本地进度。 |
| 锁定失败 | 网络、题集版本、已有锁定记录、榜单文件权限。 |
| 线上榜或总榜不更新 | 锁定是否成功、广播是否送达、榜单接口是否可读。 |
| 线下题目不推进 | 时间轴状态、轮次、音频播放、服务端调度。 |
| 主持人无法操作 | 主持人令牌、服务端错误、状态守卫。 |

## 2. 模式与路由

### 2.1 根地址进入线下模式

**现象**：访问 `/` 后显示线下登记或等待主持人。

**排查**：

1. 检查地址是否残留 `?mode=offline`。
2. 检查当前标签页 `sessionStorage` 的 `bgm.mode` 是否为 `OFFLINE`。
3. 关闭该标签页并从根地址重新打开。
4. 检查路由守卫是否把查询参数错误写入浏览器长期存储。

模式只使用当前标签页的 `sessionStorage` 作为会话值；根地址缺省值固定为线上。

### 2.2 线下二维码进入线上模式

**排查**：

1. 解码二维码，确认地址为 `{publicBaseUrl}/?mode=offline&event=jisong`。
2. 对照主持人控制台二维码旁显示的地址文本，确认手机地址栏一致。
3. 检查二维码生成时使用的 `publicBaseUrl` 与活动标识。
4. 在地址末尾手动补充 `/offline` 路径或 `mode=offline` 参数后重测。
5. 主持人页面以 `localhost` 打开时，二维码对手机不可用；改用局域网地址或隧道地址重新打开控制台后再展示二维码。

### 2.3 `/play` 被送回登记页

**排查**：

1. 检查 `sessionStorage` 是否存在 `bgm.mode`。
2. 线上检查 `participantId` 与昵称。
3. 线下检查 `playerId` 与昵称。
4. 检查浏览器是否阻止 `sessionStorage`。

## 3. 线上本地进度

### 3.1 刷新后无法继续

**可能原因**：

- 浏览器处于无痕模式。
- 站点数据被清理。
- 访问域名或端口变化。
- 题集版本变化。
- 本地记录损坏。
- 浏览器禁用 `localStorage`。

**处置**：

1. 使用同一浏览器、同一标签页组、同一域名重新打开。
2. 在开发者工具 Application 面板检查 `bgm.online.progress.v1`。
3. 检查 `participantId` 是否仍存在。
4. 检查题集版本是否与当前接口一致。
5. 确认隐私模式与自动清理策略。

题集版本变化或记录损坏时，旧进度按设计失效。不要在有未提交答题的设备上清理站点数据。

### 3.2 进度存在但页面从第一题开始

**排查**：

1. 比较本地 `questionSetVersion` 与线上题集接口返回值。
2. 检查 `eventId`、`participantId` 是否一致。
3. 检查 `currentIndex` 是否超出题集范围。
4. 检查 `answers` 是否包含未知题目。

任一校验失败都会删除进度并从头开始。需要保留证据时先复制该存储项内容，再重试。

### 3.3 页面隐藏后音频继续播放

**排查**：

- 检查 `visibilitychange` 与 `pagehide` 监听是否注册。
- 检查音频暂停调用是否被异常中断。
- 检查移动浏览器后台媒体策略。
- 确认用户没有通过系统媒体控件重新播放。

页面回到前台时必须保持暂停，等待用户点击「继续答题」。

### 3.4 页面关闭后只剩未答记录

关闭事件的时间有限，最后一段播放位置可能未写入。可接受损失范围为最近 500 毫秒。选项变化与页面隐藏事件应立即保存。

## 4. 线上音频

### 4.1 点击开始无声音

**处置**：

1. 确认手机媒体音量与静音开关。
2. 确认页面处于前台并已加载音频元数据。
3. 由用户直接点击开始或继续按钮。
4. 检查线上题集接口的 `audioUrl`：本地音频可读时为 `/api/events/{eventId}/audio?mode=online`，本地缺失时为线上对象地址；`/api/events/{eventId}/audio` 在本地缺失时返回 302 到线下对象。
5. 直接请求 OSS 对象，检查状态码、`Content-Type` 与对象 ACL。
6. 检查音频文件是否可被该浏览器解码。
7. 使用开发者工具 Network 面板查看 OSS Range 请求是否成功。

浏览器拒绝自动播放时，页面回到可点击状态，不自动跳题。

### 4.2 音频卡顿或反复请求

**排查**：

- 检查公网隧道带宽。
- 检查 OSS 对象是否对 `Range: bytes=0-1023` 返回 `206`。
- 检查 OSS 对象 `Cache-Control` 与浏览器缓存状态。
- 检查音频文件码率与手机网络。
- 检查代理是否缓存了错误的 `206` 响应。

音频中断导致无法恢复时，页面进入错误状态并保留本地进度。

### 4.3 题目与音频不同步

**排查**：

1. 对照线上编排 `timeline-online.json` 检查 `audioStartMs`、`answerStartMs`、`answerEndMs`、`audioEndMs`。
2. 检查完整音频时长是否等于最后 `audioEndMs`。
3. 检查相邻题目片段是否无缝衔接。
4. 检查浏览器是否拖动或跳转音频位置。
5. 检查页面是否使用了固定定时器而非音频位置推进。

线上当前题由音频位置推导。音频与时间字段不匹配时，先修正素材与编排，不在前端加入补偿偏移。

### 4.4 最后一题结束后未进入结果页

**排查**：

- 检查音频是否到达最后 `audioEndMs`。
- 检查 `ended` 事件是否触发。
- 检查预览请求是否失败。
- 检查页面网络与本地答案结构。

浏览器提前耗尽音频数据时不得伪造结束；应显示素材或解码错误。

### 4.5 「下一题」不可用或跳转异常

**现象一：按钮不可用**

依次检查：

1. 当前题是否已选择答案；未选答案时按钮按设计禁用。
2. 当前题作答窗口是否开放；`answerEndMs` 到达后按钮不再出现。
3. 当前是否为最后一题；最后一题不渲染「下一题」。
4. `phase` 是否为 `IN_PROGRESS`；结果页与错误页不渲染该按钮。

**现象二：点击后仍停留原题**

依次检查：

1. 浏览器是否已加载音频元数据，音频元素是否可写 `currentTime`。
2. 下一题 `answerStartMs` 是否为有效非负整数。
3. 点击处理是否先定位音频，再调用顺序推进动作并同步时钟。
4. 控制台是否出现音频播放或 seek 异常。

**现象三：跳转后题目与音频不同步**

依次检查：

1. 定位目标是否为下一题 `answerStartMs`，而不是任意题号或固定偏移。
2. 当前题下标是否只前进一题，未发生回退或跨题跳转。
3. 点击后是否立即写入 `bgm.online.progress.v1`。
4. 下一题 `answerStartMs` 是否落在完整音频时长内。

手动推进跳过的音频区间不计入有效作答耗时。按钮不得扩展为上一题、任意题号跳转或回看入口。

### 4.6 切题后长时间无声

**现象**：点击「下一题」后新题已上屏、倒计时正常递减，声音持续空白 10～40 秒；同一题集中另有部分题目点击后立即出声。

**判定**：音频元素处于播放状态（`paused=false`、`currentTime` 递增、`readyState=4`），无 `waiting` 或 `stalled` 事件，输出电平持续 -180 dB。

**排查**：

1. 用 `silencedetect` 统计静音垫：超过 5 秒的静音段较多时，素材含大段静音填充，定位落点一旦提前即长时间无声。
2. 用 `ffprobe` 查看码率：同一文件内出现 32 kbps 与 160～192 kbps 混拼时，浏览器按 TOC 估算的落点会产生偏移。
3. 逐题把播放位置设到 `answerStartMs`，对照素材在该时刻的音量，区分落点偏移与素材本身静音。

**处置**：按 [`audio-seek-quality.md`](../data-and-config/audio-seek-quality.md) 重编码为 CBR 或裁掉题尾静音。前端不加入补偿偏移。

## 5. 线上预览与锁定

### 5.1 预览请求返回 409

**原因**：本地题集版本与服务端不一致。

**处置**：

1. 重新加载线上题集。
2. 清理已失效的本地进度。
3. 重新开始 attempt。
4. 确认服务部署后 `timeline-online.json` 与题库一致；该文件缺省时确认 `timeline.json` 与题库一致。

### 5.2 预览失败但答案仍在

页面保留答案与音频位置，并提供「重新获取分数」。检查：

- 网络与 API 代理。
- `answers` 是否含重复题目。
- 选项下标是否为 0 至 3。
- `participantId`、`attemptId` 是否为空。

### 5.3 锁定按钮不可用

**原因**：

- 尚未完成全部题目。
- 预览分未成功返回。
- 已有锁定记录。
- 锁定请求正在处理。

结果页只在全部题目结束后出现。未答题按 0 分处理，不阻塞锁定。

### 5.4 锁定返回 409

**原因**：该参与者已以其他 attempt 锁定。

**处置**：

1. 调用线上状态接口查询已有记录。
2. 页面进入锁定结果状态。
3. 不创建第二个线上记录。

同一 `attemptId` 重试返回首次结果；不同 `attemptId` 在已有记录后返回冲突。

### 5.5 锁定请求超时

**处置**：

1. 保留页面与本地答案。
2. 检查服务端日志是否已写入线上记录。
3. 使用同一 `attemptId` 重新提交。
4. 如状态接口显示已锁定，直接展示已有结果。

## 6. 榜单

### 6.1 线上锁定成功但线上榜无记录

**排查**：

1. 调用 `GET /api/events/{eventId}/leaderboards/online`。
2. 检查 `online_leaderboard.json` 是否写入。
3. 检查文件目录是否可写。
4. 检查文本总结是否刷新。
5. 检查请求的活动标识是否一致。

### 6.2 总榜看不到线上成绩

**排查**：

- 线上记录是否使用相同 `eventId`。
- 线下记录是否缺少 `participantId`。
- 文件中的 `participantId` 是否与线上记录一致。
- 是否把昵称当作合并键。

昵称不参与合并。历史线下记录缺少 `participantId` 时使用 `playerId`，该记录无法自动与线上身份合并。

### 6.3 线上榜混入线下成绩

线上榜只读取 `online_leaderboard.json`。检查接口是否读取了线下快照，或前端页签是否请求了错误端点。

### 6.4 线下本轮榜混入线上成绩

本轮榜只读取当前线下玩家名册与线下快照。线上锁定记录不得进入 `leaderboards.json`。

### 6.5 总榜名次变化

总榜按请求实时聚合。后续线下轮次结算或线上锁定会改变总分、耗时和名次。结果页展示锁定时刻名次，主持人查看最新名次。

### 6.6 文本总结未更新

**处置**：

1. 检查最近一次线下结算或线上锁定是否成功。
2. 检查 `leaderboard_summary.txt` 的写权限。
3. 运行 `python parse_leaderboard.py` 重新生成。
4. 比较两个 JSON 文件与文本中的条目数量。

## 7. 线下时间轴

### 7.1 到达动作时刻后未推进

**排查**：

1. 检查主持人快照的 `timelineRunning`。
2. 检查活动状态是否满足动作守卫。
3. 检查轮次结束标记是否已到达。
4. 检查音频是否正常播放。
5. 检查服务端调度日志。

**处置**：

- 暂停后恢复，检查剩余任务是否重排。
- 使用「上一题」「锁卷」「揭晓答案」「下一题」手动兜底；「上一题」在当前题揭晓后可用，回退会重新开放该题作答并保留已有作答记录。
- 偏差过大时切换轮次或重置后重新开始。

### 7.2 音频与时间轴分离

**处置**：

1. 立即暂停。
2. 检查音频播放位置与主持人快照状态。
3. 恢复后确认剩余时长按暂停时间平移。
4. 偏差超过一个题目窗口时重置本轮。

### 7.3 主持人开始播放失败

**排查**：

- 当前状态是否 `WAITING`。
- 时间轴是否已运行。
- 是否已选择轮次。
- 音频文件是否存在且可读。
- 主持人令牌是否有效。

启动接口失败时，客户端必须停止本地音频。

### 7.4 新一轮开始后无声且控制台卡顿

**现象**：上一轮结束后立即开启下一轮，服务端时间轴运行，控制台状态显示「运行中」，但音频元素已暂停或定位到错误位置；连续多名玩家提交答案时控制台明显卡顿。

**排查**：

1. 检查浏览器控制台是否收到 `revision` 小于本地已应用版本的广播。旧轮次的 `ACTIVITY_RESET`、`ROUND_ENDED` 或 `ACTIVITY_PAUSED` 在新轮次开始后执行，会暂停或定位音频。
2. 检查音频元素的 `currentTime`。新一轮音频应位于该轮 `startMs` 与 `endMs` 之间，而不是上一轮终点或新一轮终点。
3. 检查 Network 面板中 `/host/state`、`/host/rounds` 与 `/leaderboard` 的请求数量。每条 `PLAYER_ANSWERED` 各触发一轮快照请求属于旧行为，会造成请求风暴。
4. 检查主持人页面是否在一个刷新窗口内合并高频广播，并且同一时刻只有一个在途快照请求。

**处置**：

- 暂停后恢复，确认音频元素定位到服务端快照的 `audioPositionMs`。
- 刷新控制台并重新登录；旧页面实例的异步事件处理无法恢复到可信状态。
- 若问题重现，记录广播的 `roundId`、`revision` 与本地已应用版本号，按 [`../backend/api-spec.md`](../backend/api-spec.md) 第 7 节核对事件顺序。

### 7.5 轮次切换后玩家列表为空

切换轮次会清空在线玩家与答题记录。该行为属于设计结果。主持人应提示参与者重新扫码加入。

### 7.6 `ROUND_ENDED` 后未生成榜单

轮次结束只停止音频与时间轴。榜单由 `FINISH` 触发。检查编排是否在 `endMs` 前包含 `FINISH`，或主持人是否手动触发结算。

## 8. 网络与 WebSocket

### 8.1 线下状态广播中断

**排查**：

1. 参与者刷新页面并重新读取线下快照。
2. 检查 Nginx `/ws` 的 `Upgrade` 与 `Connection` 头。
3. 检查公网隧道是否保持连接。
4. 检查浏览器控制台的 STOMP 重连日志。

客户端每 3 秒尝试重连，重连后主动刷新快照。

### 8.2 隧道域名 502 或超时

**排查**：

- 后端进程是否存活。
- Nginx 是否运行。
- Quick Tunnel 进程是否退出。
- 穿透目标是否指向同时提供前端与 API 的 origin。

重新启动隧道后域名可能变化，需重新展示二维码并提醒参与者使用新地址。新域名无法读取原域名的本地进度。

### 8.3 HTTPS 页面连接 WebSocket 失败

HTTPS 页面必须使用 `wss://`。检查反向代理证书、升级头与超时配置。

## 9. 数据持久化与恢复

### 9.1 后端崩溃

**影响**：

- 已写入 `leaderboards.json` 的线下快照保留。
- 已写入 `online_leaderboard.json` 的线上锁定记录保留。
- 进行中的线下轮次、在线玩家与时间轴丢失。
- 浏览器中的线上进度保留。

**恢复**：

1. 重启后端。
2. 检查健康接口。
3. 检查榜单接口与文本总结。
4. 主持人重新选择轮次并组织现场继续。
5. 线上参与者返回原页面继续本地进度。

### 9.2 启动失败并提示编排错误

日志包含轮次、条目下标与错误原因。按 [`../data-and-config/timeline-spec.md`](../data-and-config/timeline-spec.md) 修正：

- 时间递增。
- `LOAD` 与 `NEXT` 配对。
- `LOCK` 与 `REVEAL` 顺序。
- `FINISH` 位置。
- 音频片段与作答窗口。
- 题库覆盖。

### 9.3 榜单 JSON 损坏

**处置**：

1. 停止服务。
2. 复制损坏文件到独立位置。
3. 从最近备份恢复。
4. 校验 JSON 根节点为数组。
5. 启动服务并检查条目数量。

服务不得用空数组覆盖损坏文件。

### 9.4 文本总结与 JSON 不一致

运行：

```powershell
python parse_leaderboard.py
```

脚本只读取两个 JSON 文件并重写文本总结，不修改原始记录。

### 9.5 清理测试数据

活动前确认：

- `leaderboards.json` 为空数组或仅含正式快照。
- `online_leaderboard.json` 为空数组或仅含正式锁定记录。
- `leaderboard_summary.txt` 与 JSON 一致。

删除测试记录前先备份，避免误删正式成绩。

## 10. 诊断命令

### 10.1 健康检查

```powershell
Invoke-RestMethod http://localhost:8080/api/health
```

## 11. 现场应急顺序

1. 保留当前页面与浏览器存储。
2. 截取错误信息与主持人快照。
3. 检查健康接口与网络。
4. 暂停线下时间轴，避免音频继续跑离题目。
5. 确认线上记录是否已写入。
6. 按榜单文件恢复，不重建整场。
7. 主持人手动兜底完成当前轮，再修复环境。
8. 活动结束后备份全部 JSON 与文本总结。
